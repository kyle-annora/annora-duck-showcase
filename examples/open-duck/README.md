# Open Duck Mini v2 · source and display preparation

This package adapts Open Duck Mini v2 for an independent Annora presentation.
It preserves source identity and rigid joint transforms, while preparing lighter
browser geometry. It does not run the upstream viewer or robot software.

- Original robot: [Antoine Pirrone and contributors](https://github.com/apirrone/Open_Duck_Mini).
- Asset distribution: [Open Duck Mini Viewer](https://github.com/mertcookimg/Open_Duck_Mini_Viewer/tree/dfdb84ef3ae2405e5f115b32f48471331dc65d78/public/assets/open_duck_mini_v2), pinned to `dfdb84ef3ae2405e5f115b32f48471331dc65d78`.

## Reproduce

Requires Node.js 22.13+ and Python 3.9+. Keep preparation-only Python dependencies
in a virtual environment; the browser does not download them or a CAD kernel.
From the repository root:

```sh
npm ci
python3 -m venv /tmp/annora-duck-preparation
/tmp/annora-duck-preparation/bin/pip install -r examples/open-duck/requirements-preparation.txt
python3 examples/open-duck/fetch-assets.py
/tmp/annora-duck-preparation/bin/python examples/open-duck/prepare-geometry.py
node examples/open-duck/generate.mjs
npm run import:model -- --source examples/open-duck/model.glb --definition examples/open-duck/import-definition.json --out content/models/open-duck-review
node --test tests/open-duck-model.test.mjs
```

The importer refuses an existing output directory. Review a fresh package before
replacing the registered package. `authored-tour.json` is curated content and is
never regenerated by the converter, so camera and caption edits survive geometry
regeneration. Re-run the importer after changing that tour.

`fetch-assets.py` downloads only pinned data and parses URDF XML. It does not
execute scripts from either upstream repository. Existing original bytes can
also be used offline; the source audit test detects any changed file.

## Identity and coordinate rules

The URDF supplies 21 links, 20 joints (16 revolute, four fixed), 45 referenced STL
files and 131 visual instances. The fetched source also retains one unused STL. A visual instance is not necessarily one
indivisible engineering component: a source STL can combine touching solids.
`source-robot.json` retains each visual origin, rotation, scale, joint axis,
origin and limit. Conversion applies URDF fixed-axis RPY as `Rz × Ry × Rx`, then
adds a single Z-up → Y-up wrapper. The model is translated as a whole so its
neutral stance rests at Y=0. No source visual is independently realigned.

The curated navigation is:

| ID | Assembly |
| --- | --- |
| `open-duck` | Complete robot |
| `duck-body` | Body & power |
| `duck-head` | Head & neck |
| `duck-left-leg` | Left leg |
| `duck-right-leg` | Right leg |
| `duck-antennas` | Antennas |

Each assembly has `-shell` and `-core` subassemblies where applicable. Every
render mesh has a unique loaded name and a stable part ID in `component-map.json`.
`sourceVisualId` connects any partitioned display surfaces back to the original
URDF visual. Display surfaces have identical visual transforms and separation
vectors; they are not additional physical components.

## Geometry and line preparation

The referenced source contains 2,423,386 triangles. Offline quadric edge collapse
reduces it to 356,153 referenced triangles, using 57 unique display geometries
and 170 display mesh instances. Detailed servo cases account for much of the
source density. The head keeps all nondegenerate source faces to protect frontal
holes and its close-up silhouette (54,934 faces after duplicate/degenerate
cleanup). Smaller parts keep their original geometry when below budget.

Some source solids touch along non-manifold edges, and simplification can also
introduce coincident edge uses. The existing importer correctly refuses more
than two incident faces per welded edge. Preparation partitions those conflicting
uses into coincident display surfaces. It preserves every simplified facet and
its position; it does not disable validation, fill holes or delete internal
surfaces. `geometry-report.json` records the source and derived bounds, facet
counts, derived surface mapping and SHA-256 values. The generic importer then
validates and generates crease/silhouette data normally.

These are presentation meshes, not manufacturing CAD. The source files remain
unmodified. Triangle count exceeds the recommended 200,000 soft budget; actual
runtime checks and device limits belong in the release evaluation, not an
assumed hardware guarantee.

## Materials and presentation

White/silver shells, graphite polymer mechanisms, structural metal and bright
hardware are curated `finishFamily` hints. They make the assembly readable but
are not a verified bill of materials. Existing Engineering, Linework and Flat
highlight modes remain runtime capabilities.

Panel part IDs use separation interval `[0, 0.45]`; internal assembly groups
start later. Offsets are authored in source metres. The optional generic timing
policy affects whole-model presentation and reverses through exactly the same
function. Local assembly inspection retains its full immediate separation range.

## Motion

`DuckPresentation` is a five-second rigid quaternion clip, sampled at 60 Hz:

| Source interval | Presentation |
| --- | --- |
| 0–2.5 s | Head scan and antenna movement |
| 2.5–5 s | Restrained greeting bow and small leg pose |

All 16 joint channels use the source pivots and axes. Every sample is checked
against the source joint limits. Times 0, 2.5 and 5 return to the same neutral
world transforms after GLB export and reload. `motion-curves.json` provides the
same sampled angles, home pose and limits for host-side explanatory plots; it
is not robot telemetry. `authored-tour.json` uses these two intervals within the
20-second presentation.

No learned walking, balance, collision, force, actuator torque or operating safety
is claimed. The clip is an illustrative pose study, suitable for explaining the
source joint structure.

## Audit outputs

- `source-manifest.json`: pinned repository, file hashes and sizes.
- `source-robot.json`: parsed URDF links, visuals and joints.
- `geometry-report.json`: per-file simplification and display-surface mapping.
- `component-map.json`: source visual ↔ loaded mesh ↔ semantic ID ↔ finish.
- `conversion-report.json`: bounds, counts, neutral checks, clip and license hashes.
- `motion-curves.json`: source clip samples in degrees.
- `content/models/open-duck/preparation-report.json`: generic importer checks,
  compressed sizes, derived asset hashes and warnings.

The focused audit test checks source and derived hashes, coverage of all source
visuals, all rigid mesh identities and source-joint track bindings, limit safety,
neutral return, hierarchy membership and prepared-package source preservation.
The repository release suite and browser QA remain additional gates.
